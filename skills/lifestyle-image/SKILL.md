# 生活感生图

用户只需要表达想要什么，不要求填写机位、光线、设备等表格。读取 [手机生活感核心经验](references/phone-life.md)，内部完成必要判断，生成可查看的图片。

## 理解短请求

- 先判断：从零生成、参考图创作、编辑已有图，以及用途是独立图片还是视频背景。优先使用当前请求和上下文中已经确定的要求，自动补齐合理的拍摄条件；只用一句话交代关键假设，不逐项征求确认。
- 比例、人物是否入镜、节庆等从当前用途推断。正在做竖屏 UGC 系列时可以沿用 9:16；离开该语境后不把它当成通用强制值。只有确实影响交付、又无法合理推断的缺失信息才问用户。
- 空场景：根据地点、住宅类型、住户使用方式形成可信空间。作为人物背景时预留合适景别的站位，并提前考虑人物受光；不为了留白造出过大的房间。
- 人像：选择符合任务的持机关系与状态。商品图：先保住结构、比例、接触与展示用途。已有图：先看实际图片，定位主要问题，尽量局部修改。
- 不要求用户写复杂提示词。把补齐的方案压成具体拍摄描述；JSON、设备型号、文件名和负面词都不是可靠的万能口诀。

## 生成与收尾

先确认当前 Agent 有可用的图片生成／编辑工具，并按该工具的实际契约执行；有内置生图时默认使用内置工具。若环境提供 imagegen 技能，按需读取其工具说明。没有生图能力时说明缺少的工具，可以先交付提示词，但不能把提示词或占位图说成已生成图片。本技能不附带模型、API 密钥或额度，也不授予额外付费、上传或外部发布权限。跨模型只在用户明确要求时使用已核对的渠道，不把同模型再生成冒充跨模型。

先读取本地参考图；给每张图明确角色。生成后直接看图：主体是否自然、商品是否正确、光线与空间是否一致，以及手部、镜像、内搭串图等具体破绽。有明确且值得修的问题再针对性返修，通常最多两次；仍不成立时如实交付问题版本并说明，不无限重生或换词绕过安全拒绝。没有实质问题就停，不追加“增强真实感”。

清晰原版保留。用户明确要求实际降级后期时才做确定性的处理并保存参数；模型生成的颗粒感不叫实际后期。按工具默认方式展示图片；项目素材保存到该项目允许的产物目录，保留实际提示和输入角色，不改用户已有文件。

复用用户明确选中的人物、空间和具体拍法，不把单次生成自动认定为用户偏好。保存的是参考资产与适用条件，避免每个家庭都重复同一套道具。若缺少历史素材，只说本次的判断，不声称已读取不存在的长期记忆。

## 方法依据

核心经验可供应用中的“手机生活感”选项读取。集成时在新任务中保存规则快照，保留用户明确的主体、机位与连续性要求；更新规则不应自动改写已有任务。

需要解释方法优劣或设计实验时读 [实验结论与边界](references/evidence.md)。不把“纹理更多”“更糊”当作更真实，也不承诺任何题材一次成功。
